### Phase 2 publication validation work

No additional owner decision was needed for validation limits. The [logical and API contract](./classification-public-data-recommendation.md#phase-1-logical-and-api-shape-decisions) fixes fields, roles, revision/idempotency behavior, and publication paths. The local Node implementation uses the following limits and errors; they must be reviewed against the complete migration source and exercised in the target emulator before release.

- **Fields and batches:** 2,000 characters for vote comments, 2,048 for HTTP(S) media URLs, 4,000 for public and admin notes, 128 for IDs and display names, and at most 25 selected actions per batch. The longest checked-in modern comment is 910 characters. The belt enum and action/target combinations are checked server-side. The current export has no belt outside the enum.
- **Pages and cursors:** default 25, maximum 100 for vote detail and publication history; staged actions have a bounded 25/default, 100/maximum list. Vote detail sorts by `updatedAt` descending with Firestore's document-ID tie break and rejects stale entry revisions. Publication history sorts by `lastPublishedAt` descending with the same tie break. Malformed or missing cursor documents return `invalid_cursor`; target-emulator pagination boundary tests remain.
- **Retry retention:** command operations record request digest and response for seven days, with planned Firestore TTL on `expiresAt`; same-key/same-payload retries return the stored result and changed-payload retries return `409 idempotency_conflict`. After TTL deletion, the same key may execute again, so clients must not retry an uncertain publication indefinitely; use the publication list/detail to reconcile older timeouts.
- **Transitions and errors:** only nonpublished actions are editable; batch publication requires Staged and `omitChangelog=false`; single Publish Now applies the complete saved decision and leaves unrelated staged actions alone. The API uses `invalid_request`/`invalid_cursor` (400), `unauthorized` (401), `forbidden` (403), missing-resource codes (404), and `revision_conflict`, `duplicate_vote`, `idempotency_conflict`, or invalid-transition codes (409). Stale revision and duplicate-vote errors include the current record for recovery. Focused tests cover replay, changed-payload conflict, ownership, immutable publication, and the selected-action boundary.

These are implementation choices under the existing contract. Bring a choice back to the owner only if it would reject existing content or change the agreed workflow or retry expectation.
