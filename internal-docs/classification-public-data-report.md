### Contract decisions captured

- One vote document per `(entryId, userId)`, with a deterministic server-derived `v_` SHA-256 document ID and the original imported ID in `sourceId`. Synthetic `u_...` identities remain distinct and admin-managed.
- `classificationEntries` is a rebuildable, role-gated summary with compact vote chips and current-vote aggregates, subscribed only inside Classification. A separate minimal `classificationEntryStates` projection carries `decisionMilestoneAt`, a durable `reopened` flag, and voter IDs to match a member's own votes. Lock and scorecard routes subscribe to that state and the signed-in member's votes, without downloading other voters' chips or detail. Comments, media URLs, and admin notes stay out of both projections.
- The existing `EntryClassificationVote` guard hides other users' current and previous votes outside Classification, and its duplicate “current votes” chip summary has been removed. Row and admin-preview chips still need the Classification summary. The preview still bundles static sample votes on lock routes; the planned reader split, not the render guard, provides the intended loading and read-cost boundary. Full vote detail is requested only for an expanded lock inside Classification and released on exit.
- `reopened=true` makes all modern votes current until the next Publish or Settle, including intermediate Pending/Staged work. A new decision milestone is set only on transition to Published/Settled. A later Sheet import cannot move it. Editing an older vote moves that one canonical vote into the current set.
- Full vote detail is a bounded eligible-reader API response. Staged changelog notes are visible to eligible readers; `adminNote` is returned only through the admin action detail and is excluded from publication snapshots. Published actions and publication events are immutable.
- The versioned API uses the existing `{metadata, data}` envelope and `private, no-store` for protected responses. The sibling OpenAPI/README and local routes now document and enforce the vote/action/publication paths, bounded fields/pages/batches, expected revisions, and seven-day idempotency retention. Focused synthetic service and route tests cover the core paths; target-environment smoke tests remain before enabling readers or writes.
- The owner clarified that `blackBelt` grants Classification reads and own-vote create/edit/delete access. Vote writes require a verified `admin`, `classificationAdmin`, `lpuMod`, `classificationTeam`, or `blackBelt` claim; only an owner or `admin`/`classificationAdmin` may edit/delete an existing vote. Admin action and publication writes still require `admin` or `classificationAdmin`. The UI already derives its vote control from `blackBelt` through `classificationTeam`; the local API guard and tests now match this policy, and the owner reports that the update was uploaded and restarted.
