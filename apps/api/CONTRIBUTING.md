# API development in the monorepo

From the monorepo root, select Node 24.21.0 with `nvm use`, verify npm 11.19.0, then run `npm ci`. Web and API share the root lockfile. Root `.npmrc` keeps dependencies nested within each workspace; Firebase Functions retains its separate install.

Run `npm run validate:api` for lint and the complete API unit suite. During implementation use `npm run test:api -- --run path/to/test.js`; reserve full validation for the phase gate. The root Husky hook also validates the API when API files or shared dependency inputs are staged. Do not install the imported API hook over the root hook.

Root `.github/workflows/api-ci.yml` validates API changes and constructs the standalone Linux release artifact. Root `.github/workflows/api-deploy-production.yml` is the enabled manual, confirmed, main-only production release path using `api-production`. The monorepo is the sole production release source following Phase 5 transfer; the owner marked the old API publication final and its repository read-only, then archived it on GitHub (`archived=true` verified). Preserve the old history and retained recovery releases; submit ongoing changes here. See `.agents/references/production-releases.md` for packaging and release boundaries.

For the Phase 3 workspace/artifact gate, API CI also accepts pushes to the exact `monorepo/phase3-npm` branch with the same API path scope. This allows CI on a reviewed branch without a default-branch merge, PR creation or manual dispatch of an unavailable workflow. Pushing that branch still requires explicit authorization. CI artifact creation does not authorize dispatching a production deployment. Root Dependabot owns workspace dependency updates through the shared lockfile; keep existing environment/branch protections and coordinate settings/release actions with Neal Bayless.
